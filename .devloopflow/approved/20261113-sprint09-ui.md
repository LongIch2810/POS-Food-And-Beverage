## API contract tổng

### Quyền và scope đọc mới
- `GET /api/v1/invoices` và `GET /api/v1/invoices/:id`: cookie auth, `invoice.read`, không body; PLATFORM_ADMIN/storeId thiếu bị guard/scope từ chối. Không yêu cầu đang có ca OPEN để đọc lịch sử.
- Hàm scope mới nội bộ `SalesService.readScope(user: UserSummary, requestedBranchId?: string): InvoiceReadScope`; type `InvoiceReadScope = { storeId: string; branchId: string | null; cashierId: string | null }`.
- Có `branch.access_all`: `storeId` hiện hành, `branchId=requestedBranchId ?? null`, `cashierId=null`; không tự ép vào user.branchId. Có `invoice.read_branch` nhưng thiếu access_all: ép branch hiện hành, `cashierId=null`. Thiếu cả hai: ép branch hiện hành, `cashierId=user.id` và join `work_shifts.user_id`; ca CLOSED được đọc.
- Không có access_all và branchId thiếu: list `403 PERMISSION_DENIED` `Tài khoản chưa được gán chi nhánh.`; detail giữ `404 NOT_FOUND` `Không tìm thấy hóa đơn.` cho ID không được đọc, kể cả cùng branch nhưng thuộc ca người khác. Scope detail phải được kiểm trước đọc items/payment/tên trong response.
- Query branch khác ở user thiếu access_all không mở rộng scope; giữ hành vi ép branch như API cũ. UUID filter phải chuẩn hoá lowercase; tham số sai dạng trả lỗi validation, ID filter khác scope không trả tên/metadata/dữ liệu của scope kia.

### GET /api/v1/invoices

| Field query | Kiểu / bắt buộc | Ràng buộc và mặc định |
|---|---|---|
| `status` | string / không | `OPEN`, `PAID`, `CANCELLED`, `ALL`; thiếu = `OPEN`; ALL chỉ là giá trị lọc, không lưu DB |
| `branchId` | UUID / không | Người có access_all chọn chi nhánh store mình; người còn lại bị ép scope hiện hành |
| `from`, `to` | string / không | ISO 8601 UTC kết thúc `Z`, ngày/giờ hợp lệ; `created_at >= from`, `< to`; có cả hai phải from < to |
| `tableId` | UUID / không | Lọc đúng table_id trong scope; UUID hợp lệ không tìm thấy trong scope → danh sách rỗng |
| `cashierId` | UUID / không | Lọc chủ ca `work_shifts.user_id`; UUID hợp lệ ngoài scope → rỗng; không lọc `created_by` |
| `limit` | string integer / không | Giữ parser hiện hành: 1..999 rồi clamp 100, mặc định 20 |
| `cursor` | string / không | opaque base64url ≤1024; malformed/scope khác → 422; không nhận từ filter cũ |
| `sort` | string / không | Chỉ `-createdAt`, mặc định `-createdAt`; thứ tự thực `(created_at DESC,id DESC)` |

- Response `200`: `{ data: InvoiceSummary[], meta: { limit, nextCursor, total, filterOptions: { tables: { id: string, name: string }[], cashiers: { id: string, name: string }[] } } }`.
- `InvoiceSummary` giữ toàn bộ field summary cũ và thêm: `{ id: string; invoiceCode: string; branchId: string; tableId: string | null; orderType: 'DINE_IN' | 'TAKEAWAY'; status: 'OPEN' | 'PAID' | 'CANCELLED'; totalAmount: number; itemCount: number; createdAt: string; workShiftId: string; workShiftStatus: 'OPEN' | 'CLOSED'; cashierId: string; cashierName: string; tableName: string | null; paymentMethod: 'CASH' | 'TRANSFER' | null }`.
- `meta.total` đếm cùng toàn bộ filter và scope, bỏ điều kiện cursor; filterOptions bỏ ngày/status/table/cashier/cursor/limit nhưng giữ scope store/branch/own. DISTINCT options chỉ gồm ID có ít nhất một invoice được đọc, gồm dữ liệu ngưng hoạt động có lịch sử, không cần lấy từ trang đang hiển thị. Sắp name rồi id để ổn định.
- Cursor lưu timestamp microsecond hiện có và id. Scope serialise có version, `user.id` của người gọi ở mọi phạm vi (kể cả MANAGER/OWNER), store, branch thực, cashier scope thực, status, from/to chuẩn, tableId, cashier filter, sort; không đưa limit vào tập điều kiện lọc. Đổi user/phạm vi/filter không dùng lại cursor; hai manager cùng branch hoặc hai owner cùng store vẫn không dùng chung cursor dù cashier scope đều null. Client xem cursor là opaque, không lưu lâu dài; cursor từ phiên bản trước không khớp scope trả `422` và UI đặt lại trang đầu qua thao tác tải lại, không suy dữ liệu.
- Query unknown/repeated array, status sai, UTC/date sai hoặc đảo khoảng/UUID sai → `422 VALIDATION_ERROR` `Bộ lọc hóa đơn không hợp lệ.`; limit sai → `422 VALIDATION_ERROR` `Giới hạn danh sách không hợp lệ.`; cursor sai → `422 VALIDATION_ERROR` `Cursor không hợp lệ.`; branch sai dạng → `422 VALIDATION_ERROR` `Chi nhánh không hợp lệ.`. Đây là tái dùng message tại `sales.service.ts:84-104`, không tạo mã lỗi mới.

### GET /api/v1/invoices/:id
- `200 { data: InvoiceDetail }`: giữ toàn bộ fields `sales.service.ts:57-72` (items/toppings snapshot, tổng, promotionCode, note, cancelReason, cancelledAt, timestamps); thêm `paymentMethod`, `workShiftStatus`, `cashierId`, `cashierName`, `tableName` có kiểu như summary.
